## Configlue とは

Configlue は **Config + glue** を組み合わせた名前です。そのまま読めば「設定を糊（のり）のように繋げる」ライブラリです。

アプリの設定は、ひとつのファイルに収まりません。出荷時の既定値、ユーザーごとの保存、会社で配るポリシー、コンテナの環境変数、デバッグ時のコマンドライン指定。置き場所も、持ち主も、寿命もバラバラです。Configlue はそれらを糊づけする役目を引き受けます。各ソースは自分が知っている項目だけを差し出し、実行時にひとつの型付きモデルとして束ねます。アプリケーションコードから見えるのは、普段どおりの C# のクラスだけです。

## 設定は難しい

設定のつらさは、読み書きのコード量ではありません。時間が経つほど、だいたい次のどれかに当たります。

- 最初はひとつの JSON で足りていたのに、ユーザー別・環境別・配布ポリシーと増えていき、どの値がどこから来たのか分からなくなる。
- ファイル全体を読み替える作りにしたせいで、一項目の保存がよその項目を壊す。コメントや書式も消える。
- 環境変数やコマンドラインの上書きを足すたびに、優先順位のルールがコードの中に散らばる。
- 項目を増やした・名前を変えた途端、古いファイルの扱いが決まらず、移行が「いつかやる」仕事になる。

Configlue はこの「増えた後の設定」を前提にしています。出どころごとにソースを分け、存在する項目だけを重ね、書き込みは選んだ相手だけに戻す。そうしておけば、後からソースを足しても、古いファイルを捨てなくて済みます。

## Configlue の特徴

<CardGrid stagger>
  <Card title="全部は読み込まない" icon="layers">
    設定を一度に丸ごと読むのではなく、各ソースが持つ項目だけを出し合って組み立てます。ない項目は「ないまま」扱うので、未設定と既定値を取り違えません。
  </Card>
  <Card title="出どころごとに向き合う" icon="magnifier">
    値は出どころとセットで扱います。`Database.Host` がどのソースから来たのかを辿れ、保存するときも相手を指定できます。触っていないソースには触りません。
  </Card>
  <Card title="統合と移行を見据える" icon="arrow-right">
    ファイル分割、セクション共有、リモート参照、スキーマの版管理、保存場所の引っ越しまでを同じ考え方で扱います。設定の置き場所や形が変わっても、アプリ側の読み書きは変えずに済みます。
  </Card>
  <Card title="DI の有無を選ばない" icon="puzzle">
    同じモデル定義・ソース定義が、DI なしのコンソールやデスクトップアプリでも、DI ありの ASP.NET Core や Worker Service でも動きます。`IOptions<T>` として受け取ることもできます。
  </Card>
  <Card title="書き心地は普通の C#" icon="pencil">
    読み取るのは普通のクラスのインスタンスで、書き込みは生成 Patch の `SaveAsync(patch => patch.Name = "Ada")` で行います。Patch で Set/Unset する疎なメンバーを指定できます。
  </Card>
  <Card title="運用の道具も揃える" icon="approve-check">
    変更通知、バリデーション、バックアップ付きの安全な保存、JSON Schema の出力、NativeAOT 対応まで備えています。小さく始めて、そのまま本番の運用に持ち込めます。
  </Card>
</CardGrid>
