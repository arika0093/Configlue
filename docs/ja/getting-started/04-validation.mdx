---
title: "STEP 5: 変更を監視して検証する"
description: 外部からの変更を受け取り、不正な設定値を拒否する。
---

import { Steps } from '@astrojs/starlight/components';

初心者向けチュートリアルの最後に、変更通知と検証を追加します。どちらも、基本の読み書きとレイヤー構成を理解した後で使う方が挙動を追いやすい機能です。

<Steps>

1. ### 検証属性を追加する

   ```csharp
   using System.ComponentModel.DataAnnotations;

   [ConfiglueModel("tutorial.settings", Version = 1)]
   public partial class AppSettings
   {
       [Required, MinLength(3)]
       public string Name { get; set; } = "ExampleApp";

       public ServerSettings Server { get; set; } = new();
       public List<string> EnabledFeatures { get; set; } = [];
   }

   public class ServerSettings
   {
       public string Host { get; set; } = "localhost";

       [Range(1, 65535)]
       public int Port { get; set; } = 8080;
   }
   ```

   通常のランタイムでは DataAnnotations の検証が既定で有効です。不正な値を保存すると `ConfiglueValidationException` が発生します。

2. ### 有効値の変更を購読する

   ```csharp
   var state = context.GetState<AppSettings>();

   using var subscription = state.OnChange(updated =>
       Console.WriteLine($"Port changed to {updated.Server.Port}"));
   ```

   ファイルなど監視可能なソースが変化し、新しい有効値を正常に解決できると `OnChange` が呼ばれます。

3. ### 再読み込みの失敗を別に受け取る

   ```csharp
   var diagnostics = context.GetDiagnostics<AppSettings>();

   using var failures = diagnostics.OnReloadFailed(exception =>
       Console.Error.WriteLine(exception.Message));
   ```

   バックグラウンドの再読み込みで有効な設定を作れなかった場合、その失敗は `OnChange` ではなく diagnostics から通知されます。

</Steps>

ここまでで、1つのソース、疎な保存、レイヤー、値の出所、読み取り専用の上書き、変更監視、検証を扱いました。暗号化、HTTP、スキーマ移行、NativeAOT、YAML などは、この基本ルートの前提ではなく目的別の機能として扱います。
