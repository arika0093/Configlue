# STEP 6: HTTP ソースに対応する

組織全体の配布ポリシーやクラウド上の設定など、リモートサーバーから配信される設定を取り込みたいケースがあります。
ここでは、基本構成である **CommonSource** の上に、追加レイヤーとして **HTTP ソース** を重ねる方法を学びます。

<Steps>

1. ### モデルにリモート用のプロパティを追加する

   全社共通のセキュリティポリシーなど、リモートから供給される設定項目をモデルに追加します。

   ```csharp
   using Configlue;

   [ConfiglueModel("tutorial.settings", Version = 1)]
   public partial class AppSettings
   {
       public string Name { get; set; } = "ExampleApp";
       public ServerSettings Server { get; set; } = new();
       public PolicySettings? Policy { get; set; } // リモートから供給されるポリシー
   }

   public class PolicySettings
   {
       public bool AuditLogRequired { get; set; }
       public int MaxLoginAttempts { get; set; } = 5;
   }
   ```

2. ### CommonSource の上に追加ソースを重ねる

   プリセットのスコープ内で HTTP ポリシー層を宣言します。この層の優先順位は他の組み込み層より高く固定されています。

   <Tabs syncKey="di">
   <TabItem label="DI なし">

   ```csharp
   using Configlue;
   using Configlue.Source.Presets;

   var httpClient = new HttpClient { BaseAddress = new Uri("https://policy.example.com/") };

   conf.UseCommonSources(sources =>
   {
       sources.WithGlobal("TutorialApp");
       sources.WithLocal();
       sources
           .WithHttpPolicy("https://policy.example.com/api/policy", httpClient, id: "policy")
           .FallbackCondition(StateFallbackCondition.NotFoundOrUnavailable);
       sources.Add<AppSettings>();
   });
   ```

   </TabItem>
   <TabItem label="DI あり">

   ```csharp
   using Configlue;
   using Configlue.Source.Presets;

   // HttpClient を DI に登録
   builder.Services.AddHttpClient("policy", client =>
   {
       client.BaseAddress = new Uri("https://policy.example.com/");
   });

   builder.Services.AddConfiglue(conf =>
       conf.UseCommonSources(sources =>
       {
           sources.WithGlobal("TutorialApp");
           sources.WithLocal();
           sources
               .WithHttpPolicy(
                   "https://policy.example.com/api/policy",
                   provider => provider!.GetRequiredService<IHttpClientFactory>().CreateClient("policy"),
                   id: "policy")
               .FallbackCondition(StateFallbackCondition.NotFoundOrUnavailable);
           sources.Add<AppSettings>();
       })
   );
   ```

   </TabItem>
   </Tabs>

   HTTP ソースは既定で読み取り専用として動作します。
   HTTP 層は固定優先順位に従って、ファイル層よりも上位で評価されます。

3. ### リモートサーバーに接続できないときの挙動

   `FallbackCondition = StateFallbackCondition.NotFoundOrUnavailable` を指定しているため、ネットワーク障害やサーバーダウンが発生しても例外でプロセスが停止することはありません。
   HTTP レイヤーは自動的にスキップ（フォールスルー）され、下位のローカルファイルやモデルの初期値が使われます。

   復旧後にリモートから設定が取得できた場合、Configlue のポーリング監視によって自動的に最新値がマージされます。

4. ### 保存時の注意点

   STEP 5 の環境変数と同様に、HTTP ソースから提供されている項目をローカルから書き換えようとすると競合が発生します。
   リモート値に干渉しないプロパティ（`Server.Port` など）は、通常通り `SaveAsync` でローカルファイルに保存できます。

</Steps>
