# アーキテクチャ

Configlue は [Configuration.Writable issue #113](https://github.com/arika0093/Configuration.Writable/issues/113) と [issue #118](https://github.com/arika0093/Configuration.Writable/issues/118) にあるソースとフラグメントの設計を踏襲します。

## 境界

- **ソース**は論理的な設定スナップショットを提供し、読み取り、書き込み、監視機能を独立して持てます。
- **リソース**はファイル、データベースレコード、HTTP レスポンスなどの物理エンドポイントです。
- **コーデック**はリソース I/O を行わず、バイト列と型付き値を変換します。
- 生成された**フラグメント**は、メンバーが未設定か、null や既定値を含めて存在するかを記録します。
- 解決、マイグレーション、投影、書き込み計画はフラグメントを操作し、アプリケーションコードは通常のモデルを編集します。

論理スキーマと物理ストレージ構成は独立しています。複数のソースがひとつのモデルの部分木に値を提供でき、複数のバインディングが同じリソースを共有できます。各論理ソースは物理リソースを表す `ResourceId` を公開できます。セクションビュー、ZIP エントリビュー、投影ソースはこの ID を維持し、後続の書き込み調整に使います。

明示的な `ApplyPatchesAsync` は保存前にソース単位のパッチを計画し、同じ `ResourceId` を持つ互換性のあるセクション更新をグループ化して物理リソースを一度だけ書き込みます。共有リソースをバッチ処理できないバックエンドや、範囲が重なる更新は書き込み前に失敗します。

プロジェクトは役割ごとに `src/` 直下に配置します。`Configlue.Provider.Json`、`.Xml`、`.Yaml` は形式コーデックとセクションリソース、`Configlue.Source.Environment` は環境変数からフラグメントへの変換、`Configlue.Resource.Zip` は ZIP エントリー、`Configlue.Resource.Http` は ETag リビジョン付きの HTTP 通信を扱います。`Configlue.Core` はファイルリソースを含みます。任意のプロバイダー、ソース、リソースパッケージは個別に参照できます。

## 実装状況

基盤として、バックエンドに依存しない読み書き・監視契約、優先度付きソース解決、ソース契約のマイグレーションと投影、プロパティ単位の由来説明、生成フラグメント用の読み取り専用環境変数ソース、JSON/XML/YAML セクション、ZIP エントリー、選択ソース間のマイグレーション、再試行可能な複数ソースから複数宛先へのストレージ移行、検証済みの論理ソース退役、リソース単位にまとめるソースローカルな複数書き込み、バックアップと復元に対応するリビジョン確認付きファイル、生成フラグメントのマージ・意味的差分・パッチ、JSON/XML/YAML コーデック、JSON Schema 出力、スキーママイグレーションチェーン、保存時検証、キー付き DI プロファイル、DI ソースビルダー、実行時プロファイルレジストリ、永続プロファイルカタログ、Microsoft Options アダプター、変更通知、非同期読み取り・保存・編集セッションを実装しています。

編集で計画したソースが他ソース所有の値を削除する場合や、高優先度ソースに隠される場合は保存前に `StateConflictException` になります。別リソースへの書き込みは原子的ではありません。ソース退役は現在のオプションインスタンスにだけ適用され、保存データは残ります。次回起動に向けてアプリケーション側の登録を変更する必要があります。プロバイダーごとの変更監視方針など、今後の作業が残っています。現状は Configuration.Writable をすべて置き換える完成品ではなく、アーキテクチャの基盤です。
