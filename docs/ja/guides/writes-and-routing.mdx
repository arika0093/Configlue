---
title: 書き込みとルーティング
description: 意味的な編集を選択したソースへ保存します。
---

`StateWriteRoute.To("source-id")` で通常の書き込み先を指定します。`SaveAsync` は値または更新コールバックを受け取り、コールバックには現在のモデルのディープコピーを渡します。

```csharp
await writable.SaveAsync(settings => settings.Database!.Host = "db.internal");

using var edit = await writable.BeginConfigureAsync();
edit.Value.TimeoutSeconds = 20;
var result = await edit.SaveAsync();
```

編集セッションは開始時に各ソースのリビジョンを記録します。保存前にそのリビジョンを確認するため、競合する変更があれば新しい設定を黙って上書きせず `StateConflictException` を返します。

## 変更パスを振り分ける

`StateWritePlan` を渡すと、変更パスごとに書き込み可能なソースを選べます。最も具体的なパスが優先されるため、`Database.Password` は広い `Database` の指定より優先されます。

```csharp
var plan = new StateWritePlan(new Dictionary<string, string>
{
    ["Database"] = "database-settings",
    ["Database.Password"] = "secrets",
});

await writable.SaveAsync(
    settings => settings.Database!.Password = "updated",
    plan);
```

編集前にパスと宛先が検証されます。Configlue は各ソースの意味的な差分を適用し、書き込み前に解決後のモデルとソースのリビジョンを確認します。別々の物理リソースへの複数書き込みは原子的ではありません。

## 生成パッチを適用する

呼び出し元が変更するメンバーを把握している場合は、生成された `Model.Patch` を使います。`ApplyPatchAsync` は指定済みの書き込み先ソースに適用します。`ApplyPatchesAsync` はソースごとのパッチを受け取り、同じリソースを共有する互いに重ならないセクション更新を一度の物理書き込みにまとめます。重複する範囲は計画時に拒否します。

Append と SetUnion の編集は書き込み先ソースのコレクション部分に基づいて再適用されます。他のソースが所有する値を削除する編集や、より高優先度の値に隠れる編集は `StateConflictException` になります。
