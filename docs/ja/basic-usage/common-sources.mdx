Configlue の設定設計において、中心となるのが **CommonSource**（`UseCommonSources`）です。
標準的な各レイヤーを簡潔に宣言できます。スコープ内で宣言したレイヤーだけが有効になります。

## なぜ CommonSource を基本にするのか

実運用における設定は、単一のファイルでは完結しません。

- 出荷時やユーザー全体で共有するデフォルト設定
- 開発時や作業環境ごとのローカルな上書き
- コンテナ環境や CI で差し込む環境変数
- 起動時に手動で指定する特定の設定ファイルやコマンドライン引数

これらを手動で組み立てると、パスの解決や優先度付けのコードが重複し、設定の追加や移行が難しくなります。
`UseCommonSources` を利用すると、宣言したレイヤーに固定された優先順位が適用されます。

## レイヤー構成と優先順位

優先順位の低い順に、次のレイヤーが定義されています。

| 層 | 有効化の条件 | 保存場所・入力源 | 既定の書き込み可否 |
| --- | --- | --- | :---: |
| **Global（共通）** | `WithGlobal` | OS 標準のユーザー設定フォルダー | 書き込み可能 |
| **Local（ローカル）** | `WithLocal` | カレントディレクトリのファイル | 書き込み可能 |
| **Explicit（指定ファイル）** | `WithExplicit` | 呼び出し側が指定するファイル | 書き込み可能 |
| **Environment（環境変数）** | `WithEnvironment` | プロセス環境変数 | 読み取り専用 |
| **Arguments（引数）** | `WithCommandLine` | コマンドライン引数 | 読み取り専用 |
| **HTTP** | `WithHttpPolicy` | リモート JSON ポリシー | 読み取り専用 |

source identity と優先度（0、100、200、300、400、500）はプリセット内部で割り当てられます。
通常の `SaveAsync` は最も優先順位の高いファイル層に書き込みます。`DefaultWriteLayer` で別のファイル層を選択できます。
登録したすべてのファイル層は semantic selector から明示的に書き込み可能です。
## 基本的な使い方

複数モデルに同じプリセットを適用する場合は、`Configlue.Source.Presets` のスコープビルダーを使います。宣言したソースだけが有効になり、優先順位は Global < Local < Explicit < Environment < Arguments < HTTP で固定です。
YAML または XML を共通ファイル層で使う場合は、`Configlue.Source.Presets.Yaml` または `Configlue.Source.Presets.Xml` パッケージを追加します。これらは個別の任意依存であり、使用しない形式の Provider は不要です。

```csharp
using Configlue;
using Configlue.Source.Presets;
using SharpYaml;
using System.Text.Json;

await using var context = ConfiglueApp.CreateContext(conf =>
    conf.UseCommonSources(sources =>
{
    sources.WithGlobal("ExampleApp", filename: "settings.yaml")
        .Yaml(serializerOptions: new YamlSerializerOptions())
        .FileResourceOptions(new FileResourceOptions { CreateBackup = false });
    sources.WithLocal().Json(new JsonSerializerOptions());
    sources.WithEnvironment("EXAMPLE");
    sources.Add<AppSettings>();
    })
);
```

`WithCustom(CommonSourceLayer.Global, ...)` のように指定すると、組み込みレイヤーの間にカスタムソースを追加できます。各 Provider のシリアライザー・リソース設定と、CommandLine のマッピング API を利用できます。

宣言した層だけが有効になります。通常の保存先は、設定されたファイル層のうち最も優先順位が高い層です。別のファイル層に保存したい場合は `DefaultWriteLayer` で指定できます。

```csharp
using Configlue;
using Configlue.Source.Presets;

await using var context = ConfiglueApp.CreateContext(conf =>
    conf.UseCommonSources(sources =>
    {
        sources.WithGlobal("ExampleApp", filename: "appsettings.json");
        sources.WithLocal();
        sources.WithExplicit(userSpecifiedPath);
        sources.WithEnvironment("EXAMPLE");
        sources.DefaultWriteLayer(CommonSourceLayer.Local);
        sources.Add<AppSettings>();
    })
);
```

DI 登録では同じ `conf.UseCommonSources(...)` を `AddConfiglue` 内で呼び出します。ファイル層には既存 Provider の API を利用でき、たとえば `sources.WithGlobal("ExampleApp").Yaml()` や `.FileResourceOptions(...)` を指定できます。

## セマンティックセレクターによる明示保存

通常の `SaveAsync` は既定の保存先（通常は Local）に書き込みますが、特定の層を指定して保存することも可能です。
文字列で ID を指定する代わりに、型安全な `CommonSource` セレクターを使用します。

```csharp
var sourceAdmin = context.GetSources<AppSettings>();

// ユーザー共通設定 (Global) に保存
await sourceAdmin.Source(CommonSource.Global).SaveAsync(patch =>
{
    patch.Theme = "Dark";
});

// ローカル設定 (Local) に保存
await sourceAdmin.Source(CommonSource.Local).SaveAsync(patch =>
{
    patch.LocalPort = 8080;
});
```

## CommonSource からの発展パターン

CommonSource は Provider 固有のソースと組み合わせられます。

### パターン 1: コマンドライン引数を重ねる

コマンドラインによる設定の上書きには `Configlue.Source.CommandLine` パッケージの拡張 API を使います。

```csharp
using Configlue.Source.CommandLine;

conf.UseCommonSources(sources =>
{
    sources.WithGlobal("ExampleApp");
    sources.WithLocal();
    sources.WithEnvironment("EXAMPLE");
    sources.WithCommandLine(parseResult, mappings =>
    {
        mappings.Map(portOption, "Server.Port");
        mappings.Map(verboseOption, "Verbose");
    });
    sources.Add<AppSettings>();
});
```

コマンドライン層は固定優先順位に従って、環境変数より上位に登録されます。

### パターン 2: リモートポリシーや追加ソースを重ねる

会社の共通設定（HTTP 経由）を組み合わせる場合は、プリセットのスコープ内で HTTP 層を宣言します。

```csharp
conf.UseCommonSources(sources =>
{
    sources.WithGlobal("ExampleApp");
    sources.WithLocal();
    sources.WithHttpPolicy(
        "https://policy.example.internal/api/config",
        httpClient,
        id: "company-policy");
    sources.Add<AppSettings>();
});
```

HTTP 層は固定優先順位に従って、他の標準層より上位に登録されます。
