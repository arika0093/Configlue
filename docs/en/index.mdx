## Typed configuration state for .NET

Configlue is typed read/write configuration state for .NET. Application code reads and writes settings through a small state API, while storage and layout concerns stay outside normal application code.

It matters most when an application **edits** configuration rather than only consuming it.

## Why reading is not enough

Read-side abstractions cover a large part of the problem, but once an application edits its own settings, several questions arrive together:

- how to write settings back without leaking storage details into application code;
- how to combine multiple scopes or sources into one effective value;
- how to preserve where each value came from;
- how to choose where a change is written;
- how to evolve the schema without breaking stored data;
- how to observe external changes.

The pattern is familiar from tools such as Git, VS Code, and Chrome: layered scopes, precedence, and separate read and write targets. Configlue brings that pattern to ordinary .NET applications.

## The API your application sees

Most application code depends only on `IReadOnlyState<T>` and `IWritableState<T>`. One compact read/write flow looks like this:

```csharp
var settings = ConfiglueApp.GetState<AppSettings>();

var current = await settings.GetValueAsync();

await settings.SaveAsync(patch =>
{
    patch.Theme = "Dark";
});
```

Application code says what to read or write. How settings are stored and combined stays configured elsewhere. [Concepts](concepts/) defines terms such as source, effective value, and provenance precisely.
