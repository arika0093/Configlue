---
title: Schema and storage migrations
description: Upgrade persisted fragments and move source contributions safely.
---

Set a stable model ID and schema version in `[ConfiglueModel]`. The JSON codec stores this metadata beside the serialized fragment, and codecs can expose metadata through `IStateSchemaMetadataReader`.

Implement `IStateSchemaMigration<TFragment>` and register it with dependency injection to transform an older fragment during reads. Migration chains are scoped to the model fragment and let a source evolve its stored representation without changing the resolved application model all at once.

When an older version has a different generated fragment shape, declare its model on the current model and create a typed decoder table:

```csharp
[ConfiglueModel(1, Id = "app-settings")]
public partial class SettingsV1
{
    public string? OldName { get; set; }
    public int RetryCount { get; set; }
}

[ConfiglueModel(2, Id = "app-settings")]
[ConfigluePreviousVersion(typeof(SettingsV1))]
public partial class Settings
{
    public string? Name { get; set; }
    public int RetryCount { get; set; }
}

var history = Settings.CreateSchemaDispatcher(
    new JsonStateCodec<SettingsV1.Fragment>(),
    migrateV1: static old =>
    {
        var builder = Settings.Fragment.FromPrevious(old).ToBuilder();
        if (old.OldName.IsPresent)
        {
            builder.Name = old.OldName;
        }

        return builder.Build();
    });

var source = SerializedStateSource.FromResource<Settings.Fragment>(
    "settings",
    resource,
    new JsonStateCodec<Settings.Fragment>(),
    schemaDispatcher: history);
```

`FromPrevious` transfers same-name members with compatible types and preserves missing, present-null, and present-default values. Supply a custom migration for renames or other transforms. The reader selects a historical codec from the resource or payload schema metadata before decoding; when metadata is absent, it treats the payload as the current shape. A same-ID version without a registered decoder, including a future version, fails clearly. The dispatcher uses statically typed codecs; trimming and NativeAOT support depends on the codec metadata you provide.

For a storage move, call `IWritableOptions<TModel>.MigrateSourceAsync(sourceId, targetId)` to copy one source contribution to another writable source. Use `MigrateSourcesToTargetsAsync(sourceIds, targetProjections)` to merge selected contributions and project them into one or more targets. Each target is revision-checked and verified; completed targets are skipped on retry if a later destination fails.

Multi-target writes are not atomic. Optional source retirement changes only the current options instance and is allowed after every target verifies and the effective model remains unchanged. It does not delete the original backing data, and the application's source registration must be updated for future starts.
