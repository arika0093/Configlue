The final beginner step adds two behaviors that matter after basic reading and layering are understood: change notifications and validation.

<Steps>

1. ### Add validation attributes

   ```csharp
   using System.ComponentModel.DataAnnotations;

   [ConfiglueModel("tutorial.settings", Version = 1)]
   public partial class AppSettings
   {
       [Required, MinLength(3)]
       public string Name { get; set; } = "ExampleApp";

       public ServerSettings Server { get; set; } = new();
       public List<string> EnabledFeatures { get; set; } = [];
   }

   public class ServerSettings
   {
       public string Host { get; set; } = "localhost";

       [Range(1, 65535)]
       public int Port { get; set; } = 8080;
   }
   ```

   DataAnnotations validation is enabled by default for ordinary runtime builds. Invalid saves throw `ConfiglueValidationException`.

2. ### Subscribe to effective-value changes

   ```csharp
   var options = context.GetOptions<AppSettings>();

   using var subscription = options.OnChange(updated =>
       Console.WriteLine($"Port changed to {updated.Server.Port}"));
   ```

   File watchers and other watchable sources use the same `OnChange` callback after a new effective value is resolved successfully.

3. ### Observe reload failures separately

   ```csharp
   var diagnostics = context.GetDiagnostics<AppSettings>();

   using var failures = diagnostics.OnReloadFailed(exception =>
       Console.Error.WriteLine(exception.Message));
   ```

   A background reload that cannot produce a valid configuration is reported through diagnostics rather than through `OnChange`.

</Steps>

You now have the concepts needed for the functional guides: one source, sparse saves, layering, provenance, read-only overrides, watching, and validation. Encryption, remote resources, schema migration, NativeAOT, and alternate formats are separate topics rather than prerequisites.
