Putting everything into a single file conflates machine-wide defaults with project-specific overrides.
The CommonSource preset provides helpers to declare two distinct file layers: **Global (shared)** and **Local (project)**.

## The Two Layers of CommonSource

Declare both layers in the `UseCommonSources` scope:

| Layer | Location | Role | Priority |
| --- | --- | --- | :---: |
| **Global** | OS per-user configuration folder | Machine-wide defaults | Low |
| **Local** | Current directory (`settings.json`) | Project overrides | High |

### Read and Merge Rules

- **Priority overlay**: When a property exists in both files, the higher-priority `Local` value wins.
- **Fall-through**: Properties absent from `Local` preserve their `Global` values.
- **Missing files**: Missing files are skipped without throwing exceptions; settings are composed from whatever layers and model defaults exist.

## Directing Write Destinations

By default, calling `options.SaveAsync` persists changes to the highest-priority configured file, which is **Local** here.
To write to the Global file instead, use either of the following approaches:

### Approach 1: Write directly to a layer (Semantic Selector)

Use `CommonSource.Global` to retrieve a source handle for the shared layer:

```csharp
using Configlue.Source.Presets;

// Write to Global
await options.Source(CommonSource.Global).SaveAsync(patch =>
{
    patch.Name = "GlobalDefaultName";
});

// Ordinary save (writes to default Local destination)
await options.SaveAsync(patch =>
{
    patch.Name = "LocalOverrideName";
});
```

### Approach 2: Change the default write layer

```csharp
using Configlue.Source.Presets;

conf.UseCommonSources(sources =>
{
    sources.WithGlobal("TutorialApp");
    sources.WithLocal();
    sources.DefaultWriteLayer(CommonSourceLayer.Global);
    sources.Add<AppSettings>();
});
```
