title: "STEP 2: Grow the model"
description: Add nested objects and collections without changing the basic read/write workflow.
---

import { Steps } from '@astrojs/starlight/components';

A settings model can contain ordinary nested classes and collections. The registration and `GetValueAsync` / `SaveAsync` workflow stays the same.

<Steps>

1. ### Add nested settings

   ```csharp
   [ConfiglueModel("tutorial.settings", Version = 1)]
   public partial class AppSettings
   {
       public string Name { get; set; } = "ExampleApp";
       public ServerSettings Server { get; set; } = new();
       public List<string> EnabledFeatures { get; set; } = [];
   }

   public class ServerSettings
   {
       public string Host { get; set; } = "localhost";
       public int Port { get; set; } = 8080;
   }
   ```

   Nested classes do not need `[ConfiglueModel]` when they are part of the root model.

2. ### Save a nested member sparsely

   ```csharp
   await options.SaveAsync(patch =>
   {
       patch.Server.Port = 9000;
   });
   ```

   This operation contributes a value for `Server.Port` without turning every model default into persisted state.

3. ### Replace a collection when needed

   ```csharp
   await options.SaveAsync(patch =>
   {
       patch.EnabledFeatures = ["audit-log", "metrics"];
   });
   ```

   For settings screens that edit many values as a mutable model, use an edit session later; patch saves remain the simpler choice for known fields.

</Steps>
