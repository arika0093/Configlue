title: "STEP 4: Add environment overrides"
description: Add a read-only high-priority source and understand shadowed writes.
---

import { Steps } from '@astrojs/starlight/components';

Environment variables introduce the first read-only override. This makes the difference between read priority and write destination visible.

<Steps>

1. ### Add the environment layer

   ```csharp
   await using var context = ConfiglueApp.CreateContext(config =>
       config.UseCommonSources(sources =>
       {
           sources.WithGlobal("TutorialApp");
           sources.WithLocal();
           sources.WithEnvironment("EXAMPLE");
           sources.Add<AppSettings>();
       }));
   ```

2. ### Set a nested value

   Property paths use double underscores.

   ```sh
   export EXAMPLE__SERVER__PORT=9000
   ```

   The environment source has higher priority than the file layers, so the effective `Server.Port` becomes `9000`.

3. ### Inspect shadowing before saving

   ```csharp
   var options = context.GetOptions<AppSettings>();
   var details = await options.GetDetailsAsync();

   Console.WriteLine(details.Server.Port.Value);
   Console.WriteLine(details.Server.Port.IsEditable);
   Console.WriteLine(details.Server.Port.Source?.Locator);
   ```

   A writable Local source may exist even when the effective value cannot currently be changed through the normal save route because the read-only environment source shadows it.

4. ### Handle conflicts explicitly

   Trying to save a different value for a member that remains shadowed can raise `StateConflictException`. Remove the override, save another member, or change the source topology instead of assuming that a successful file write would change the effective configuration.

</Steps>
