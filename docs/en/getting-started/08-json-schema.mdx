title: "Export JSON Schema"
description: Generate schemas from models for editor autocompletion and CI validation.

import { Steps } from '@astrojs/starlight';

To catch configuration typos before runtime, Configlue exports JSON Schema from the models in your built application.
This enables rich autocompletion in editors such as VS Code and static validation in CI workflows.

Schema generation is a build-time concern. The `Configlue.JsonSchema.MSBuild` package discovers `[ConfiglueModel]` types in the built assembly by reflection and writes versioned schema files during `Build`.
It is a direct-only development dependency: referencing it does not add `JsonSchema.Net` or any schema-generation code to your application's runtime or package graph.

<Steps>

1. ### Reference the build package

   ```shell
   dotnet add package Configlue.JsonSchema.MSBuild
   ```

   Your project must define at least one `[ConfiglueModel]` type; the analyzer from `Configlue.Generator` emits the model.

2. ### Build the project

   Building generates one schema per model. For a model declared as `[ConfiglueModel("tutorial.settings", Version = 1)]`, this writes `schemas/tutorial.settings.v1.json` under the solution root.
   Supported DataAnnotations (`[Range]`, `[MinLength]`, `[EmailAddress]`, and so on) map to JSON Schema constraints.

   ```shell
   dotnet build
   ```

   The generated schema describes the persisted document shape: `$version` is pinned with `const`, every model member is optional, and unknown members are rejected.

3. ### Reference the schema in settings

   When serializing settings, configure a serializer or source with schema reference capabilities so that a `$schema` property is added to the root document:

   ```json
   {
     "$schema": "./schemas/tutorial.settings.v1.json",
     "$version": 1,
     "Name": "ExampleApp",
     "Server": {
       "Host": "localhost",
       "Port": 8080
     }
   }
   ```

</Steps>

## Configuration

Set these MSBuild properties to customize generation:

| Property | Default | Purpose |
| --- | --- | --- |
| `ConfiglueGenerateSchemas` | `true` | Set to `false` to opt out of automatic generation. |
| `ConfiglueSchemaOutputPath` | solution-root `schemas` | Explicit output directory; relative paths resolve against the project directory. |
| `ConfiglueSchemaBaseUri` | empty | Absolute URI used for generated `$id` values and to add a root `$schema` property. |
| `ConfiglueSchemaDocumentLayout` | `Simple` | `Simple` stores `$version` inline; `Detailed` uses the `$configlue`/`$value` envelope. |
| `ConfiglueSchemaVersionProperty` | `$version` | Version property name used by the `Simple` layout. |
| `ConfiglueSchemaTargetFramework` | first target framework | Target framework whose build output is inspected. |

The default output root is the explicit `ConfiglueSchemaOutputPath` when set, then `$(SolutionDir)/schemas`, then the nearest ancestor directory containing a `.sln` or `.slnx` followed by `schemas`, and finally `$(MSBuildProjectDirectory)/schemas`.
Schemas are written once per project build even when the project multi-targets, and unchanged schema files are not rewritten.

To regenerate schemas explicitly for tooling or CI, run the `GenerateConfiglueSchemas` target after a build:

```shell
dotnet msbuild -t:GenerateConfiglueSchemas
```
