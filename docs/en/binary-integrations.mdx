## Compiler baseline

`Configlue.Generator` targets .NET Standard 2.0, builds against Roslyn 4.3.1,
and emits C# 9 syntax for model kinds supported by C# 9. Record structs require
C# 10 in the consumer's own declaration. Generated model registration is lazy
and uses the model descriptor; it does not require module initializers or assembly scanning.

The compatibility test project actually runs the generator on Roslyn 4.3.1 and
compiles its output with C# 9, including JSON and MessagePack support, historical
schemas, nested structural models, collections, global namespaces, and escaped identifiers.
This checks compiler compatibility, not execution inside Unity. Unity's documented
compiler constraints are described in its [compiler manual](https://docs.unity3d.com/6000.0/Documentation/Manual/csharp-compiler.html).

## MessagePack wire contract

Reference `Configlue.Provider.MessagePack`. When the provider is referenced during
generation, Configlue emits formatters for generated Fragments and nested structural
Fragments. It does not rely on another source generator discovering generated types.

`MessagePackStateCodec<TFragment>` writes a MessagePack map with two entries:

```text
{
  "$configlue": { "version": 1, "id": "your.model.id" },
  "$value": { "PropertyName": value, ... }
}
```

Fragment payload keys are case-sensitive CLR property names, not ordinal member IDs.
Absent members are omitted; present null and present default values are written.
Nested structural values use nested sparse maps. Unknown entries are skipped, and
map entries can arrive in any order. Changing declaration order does not change
member identity. Renaming a property changes its wire identity and requires an
explicit schema version/migration decision. JSON naming attributes do not rename
MessagePack keys. The earlier, unreleased integer-key prototype is not this wire format.

`MessagePackStateValueSerializer<T>` writes the same payload without the schema
envelope, for backends that store metadata separately. Historical fragments use
their own generated formatters and compose with the existing schema dispatcher.

Use `SerializedStateSource.FromResource<TFragment>` to compose a codec with any
serialized resource. `FromMessagePackFile` and the common file preset's
`.MessagePack(options)` convenience select this codec for files. Document sections
are unsupported and fail explicitly.

## Resolver customization and AOT

The typed codec selects the generated root Fragment formatter directly. Nested
structural Fragment formatters also call generated code directly. Opaque scalar
values and collections use the caller's MessagePack resolver/options. Supply explicit
or MessagePack-generated formatters for those values on an AOT host; the default
standard resolver can use reflection for ordinary values.

`ConfiglueMessagePackResolver` composes Configlue registrations with a supplied
fallback resolver. A missing scalar formatter is a setup failure, including when
MessagePack wraps it in another exception; it is not classified as corrupt data.
Generated nested formatters respect `options.Security`'s object graph depth limit.
See [MessagePack security guidance](https://github.com/MessagePack-CSharp/MessagePack-CSharp#security).

`MessagePackAotTests` exercises primitive scalars, an explicit `List<int>` formatter,
nested generated Fragments, null presence, and schema metadata without a dynamic
fallback resolver. CI runs that test from the NativeAOT executable as well as the
ordinary test assembly. This does not certify Unity IL2CPP or managed stripping.

## Compression and encryption

Reference `Configlue.Transformer.Compression` for
`CompressionStateByteTransformer.Lz4()` or `.Zstandard()`.
The optional package pins NativeCompressions 0.6.1 and targets .NET Standard 2.1
and .NET 10; Core does not depend on it. It stores native LZ4 or Zstandard frames.
Malformed compressed input becomes a recoverable `CompressionException`.
Missing or incompatible native libraries remain deployment failures, with no fallback algorithm.

Resource transformers run in registration order on reads and reverse order on writes.
Register `[aes, compression]` to obtain:

```text
write: JSON/MessagePack bytes -> compress -> encrypt -> resource
read:  resource -> decrypt -> decompress -> JSON/MessagePack bytes
```

The common SingleBinary preset offers `.WithLz4()` and `.WithZstandard()` for
compressing the complete ZIP archive. Transformer order follows the same rule.
Tests cover both algorithms with JSON/MessagePack plus AES, empty input,
incompressible small input, and malformed frames.

NativeCompressions 0.6.1 is a preview dependency. Its
[versioned Unity notes](https://github.com/Cysharp/NativeCompressions/blob/0.6.1/README.md#unity)
describe NuGetForUnity native runtime import requirements and explicitly exclude
iOS IL2CPP. Configlue's desktop tests do not establish support for a Unity player
or another native target: validate that host and architecture with its actual plugin import settings.

## Existing R3 integration

`Configlue.Extensions.R3` remains host-neutral. `ObserveValues`, `ObserveChanges`,
and `ObserveActiveValues` compose with normal R3 operators. Unity applications
must marshal UI callbacks through their R3 Unity integration or main-thread
dispatcher and dispose subscriptions with the component's lifetime. Configlue
does not require `R3.Unity`. Existing .NET R3 tests cover subscription disposal,
profile switching, concurrent notifications, and initial-read races; actual Unity
Editor/player validation remains a separate support gate.
