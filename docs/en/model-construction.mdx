# Model construction

Configlue and SparseFragments use the same constructor binding for generated root
models. A root model can use a private constructor because the generated code is
part of the model's partial declaration.

The generator prefers a parameterless constructor. Otherwise it selects a
constructor whose parameters match public readable properties by name (ignoring
case) and exact type. A setter, when present, must be public. `init` accessors are
supported. Getter-only properties bound to the selected constructor are included
in the fragment and restored through constructor arguments. Constructors are ordered by parameter count, then their symbol display
string using ordinal comparison. Parameters with `ref`, `in`, or `out` are not
supported by this binding.

Primary constructors on classes and positional record constructors use the same
binding. Their parameters must correspond to represented properties; a primary
constructor parameter used only in a private field is not a fragment member.

## Projecting a fragment

`Fragment.ToModel()` calls the selected constructor once. A present fragment
member supplies the corresponding constructor argument. An absent member uses
the parameter's declared optional default, or `default(T)` if no optional default
exists. Consequently, a required `int` constructor parameter receives `0` when
its member is absent, and a required reference parameter receives `null`.
Constructor validation and exceptions retain their normal behavior.

After construction, present writable members are projected onto the model. Absent members
retain the values established by the constructor and property initializers.
Generated projection constructors assign `init` properties within a constructor
and satisfy represented `required` properties. Required fields and required
properties that cannot be represented receive a generator diagnostic.

For a constructor that rejects its parameter defaults, supply the corresponding
members before calling `ToModel()`. This also applies to Configlue's default model
construction, which uses an empty fragment.

## Cloning

`DeepClone()` supplies cloned property values to the selected constructor. A
property bound to a constructor parameter is cloned once, and its clone is reused
by the object initializer. Thus the constructor and final property receive the
same cloned value. The source value is isolated according to the member's clone
strategy.

Getter-only properties are reconstructed by the selected constructor; no setter
or object initializer assignment is generated for them. Getter-only properties
that are not bound to that constructor are excluded from the fragment.

Undecorated structural child classes can use public constructors with matching
parameters and getter-only properties. Their generated fragments use the same
argument defaults as root fragments. Cloning also handles these child values
inside supported collections.

Structural child properties with `init` are supported when bound to the selected
public constructor. Constructor arguments restore these properties; no later
setter assignment is generated. A child with `required` properties must use a
selected constructor annotated with `SetsRequiredMembers`; any `init` properties
must also be bound to its parameters. Unbound `init` properties are not yet
supported by this construction path. Preservation of aliases and cycles
throughout the entire model graph is tracked separately from constructor binding.
