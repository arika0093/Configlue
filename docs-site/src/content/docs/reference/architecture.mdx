---
title: Architecture
description: The boundaries and current implementation status of Configlue.
---

Configlue separates logical configuration schema from physical storage topology. A source contributes a logical snapshot, a resource represents a physical endpoint, a codec translates bytes, and a generated fragment tracks member presence. Resolution, migration, projection, and write planning operate on fragments; application code edits ordinary model values.

Several logical sources can contribute to one model subtree, and multiple bindings can share a resource. Section resources and ZIP-entry resources preserve that identity so compatible writes can be coordinated. Writes across different physical resources are not atomic.

The implementation currently includes generated sparse fragments, prioritized resolution, JSON/XML/YAML codecs, JSON/XML/YAML section resources, file and ZIP resources, environment sources, source migration and projection, JSON Schema export, DI profiles, persistent profile catalogs, Microsoft options adapters, change notifications, and revision-aware writes.

For the fuller design notes, see [`docs/architecture.md` on GitHub](https://github.com/arika0093/Configlue/blob/main/docs/architecture.md). The current implementation is an architectural foundation; provider-specific watcher policies and other feature-completeness work remain in progress.
