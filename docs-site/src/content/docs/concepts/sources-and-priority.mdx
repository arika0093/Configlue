---
title: Sources and priority
description: Understand how independent state sources contribute to one model.
---

A state source has a stable logical ID, a reader, a priority, and optional writer and watcher capabilities. A source may be read-only, writable, watched, or any combination supported by its backend.

Sources are read in descending priority order. Configlue merges the members present in each sparse fragment: the higher-priority source wins for members it contains, and lower-priority sources fill the gaps. Nested models are merged member by member as well.

```csharp
var sources = new StateSourceSet<AppSettings.Fragment>([
    new("local", localReader, priority: 100),
    new("defaults", defaultsReader, priority: 0),
]);
```

This lets a local file override a few settings while retaining defaults for everything else. A read fallback condition controls whether the resolver tries the next source after a source reports `NotFound` or `Unavailable`; it does not change member-level merge behavior for successful fragments.

Reads and writes are configured separately. By default, writes use the highest-priority source that has a writer. Set `StateWriteRoute.To("local")` when ordinary edits should always target a particular writable source.

The logical source ID is distinct from the physical resource identity. Several logical section views can share one file or archive and report that shared `ResourceId` for coordinated writes.
