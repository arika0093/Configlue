# Performance measurements: 2026-09-28

## Environment and method

Measurements were taken with BenchmarkDotNet 0.15.8 on Windows 11 25H2, Intel Core i7-14700F, .NET SDK 10.0.401, and .NET 10.0.12. The machine used the High performance power plan. Both runs used BenchmarkDotNet's `ShortRun` job (one launch, three warmups, three measured iterations).

The baseline was the `a289301` revision before the allocation changes. The after run included the changes to `StateRevisionVector` and `ConfiglueOptions.ResolveCoreAsync`. The baseline suite ran all benchmark groups; after the change, the layered resolution group and `OptionsRuntimeBenchmarks.GetValueAsync` were rerun.

```shell
dotnet run -c Release --project benchmarks/Configlue.Benchmarks --no-restore -- --job short --filter '*'
dotnet run -c Release --project benchmarks/Configlue.Benchmarks --no-build -- --job short --filter '*LayeredResolutionBenchmarks*'
dotnet run -c Release --project benchmarks/Configlue.Benchmarks --no-build -- --job short --filter '*OptionsRuntimeBenchmarks.GetValueAsync*'
```

## Results

| Benchmark | Before | After | Allocation change |
| --- | ---: | ---: | ---: |
| Resolve, 1 source | 383.7 ns, 1.23 KB | 328.3 ns, 1.02 KB | -0.21 KB |
| Resolve, 4 sources | 563.9 ns, 1.89 KB | 638.1 ns, 1.68 KB | -0.21 KB |
| Resolve, 16 sources | 1,619.7 ns, 4.75 KB | 1,636.0 ns, 4.54 KB | -0.21 KB |
| GetValueAsync | 320.1 ns, 1.23 KB | 327.4 ns, 1.02 KB | -0.21 KB |

The allocation reduction is consistent across these paths. The time results are mixed: the one-source resolution sample improved, while the other two layered samples and `GetValueAsync` were slightly slower. With only three measured iterations and overlapping short-run confidence intervals, these timing differences do not establish a reliable throughput change.

The changes avoid allocating an empty nested-revision map when there are no nested revisions and avoid merging the lowest-precedence fragment into a new empty fragment. The measurements support the reduced-allocation goal. The results are exploratory and are not CI thresholds. The file persistence benchmark is sensitive to local file system and OS cache behavior and was not rerun after this code change.
