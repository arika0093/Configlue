# Performance measurements: 2026-09-28 post Issue #2

## Environment and method

Measured current `main` after the Issue #2 API and mounted-write changes with BenchmarkDotNet 0.15.8 on Windows 11 25H2, Intel Core i7-14700F, .NET SDK 10.0.401, and .NET 10.0.12. The run used the High performance power plan and `ShortRun` (one launch, three warmups, three measured iterations). These exploratory measurements are not CI thresholds.

```shell
dotnet run --project benchmarks/Configlue.Benchmarks/Configlue.Benchmarks.csproj --configuration Release --no-restore -- --job short --filter '*'
```

## Results

| Scenario | Mean | Allocated |
| --- | ---: | ---: |
| Resolve, 1 in-memory source | 366.7 ns | 1.45 KB |
| Resolve, 4 in-memory sources | 630.4 ns | 2.23 KB |
| Resolve, 16 in-memory sources | 1,620.3 ns | 5.37 KB |
| Configlue `GetValueAsync` | 373.8 ns | 1,488 B |
| Facade `GetValueAsync` | 386.6 ns | 1,488 B |
| `IOptionsMonitor<T>.CurrentValue` | 5.3 ns | 32 B |
| Publish watched change | 5.52 us | 4,081 B |
| File-backed Configlue read | 7.00 us | 2,056 B |
| `Configuration.Writable` cached read | 15.3 ns | 32 B |
| Configlue file save | 4.08 ms | 199,298 B |
| `Configuration.Writable` file save | 2.22 ms | 13,242 B |

The layered-resolution results are consistent with the previous optimized current-main run: allocations remain 1.45 KB, 2.23 KB, and 5.37 KB for 1, 4, and 16 sources. The earlier measured validation fast path reduced allocations against its pre-optimization run by 68%, 58%, and 37%, respectively. Current timings are within the short-run variation of those earlier results.

The file-save comparison still shows a substantial allocation and latency gap. These saves use each library's default document format and backup behavior, so the numbers are directional; a follow-up allocation profile is needed before changing the write pipeline. No write-path optimization was made from this short run alone.
